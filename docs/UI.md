# 界面规范

适用版本：SpireForge 0.4.2。

## 视觉与文案

- 沿用项目原配色：深蓝黑背景、冷灰文字、琥珀主操作、天蓝链接与绿色状态色。卡牌恢复原有类型色与稀有度光晕。布局和操作简化沿用0.4.0。
- 主界面分为卡牌库、中央编辑区和侧边预览。常用操作位于主区，导入、技术标识、计算限制和翻译进入次级分组。
- UI 文案正式、简洁；按钮使用动作名称，字段使用短标签，状态和计数器优先显示名称。必要后果、错误与处理步骤完整保留。
- 双语名称按当前语言显示，缺失时回退另一语言，再回退稳定标识。
- 样式集中在 `src/theme.css`，使用 `--lk-*` 语义令牌。已有 Tailwind 颜色映射到统一令牌；卡牌视觉中的类型色属于卡牌领域数据。
- 共享控件来源为 LoomKit 0.2.0，副本位于 `src/vendor/loomkit/`。`KitButton` 通过公开 `mount/update/destroy` 接口适配 React。现有 React 表单、Disclosure 和 Combobox 沿用项目原语与同一套令牌。
- 组件依赖单向：主题与通用控件 → 编辑器展示 → 规则数据与状态层。业务逻辑保留在项目模块中。

## 规则编辑

- 工作台分为「规则」「自定义状态」「模板」。分区切换保留组件和输入草稿。
- 专注编辑提供执行结构导航；点击节点会展开对应分支并聚焦。概要行呈现实际条件、数值和状态名称。
- 模板先预览，再追加到当前规则；同标识状态采用当前定义，并显示相关提示。
- 状态创建自动分配标识。主要流程为名称、描述、触发时机、叠层方式与规则；图标、翻译和限制按需展开。
- 「保存并引用」保存项目共享状态并追加一条状态规则；保存和关闭操作绑定原项目与草稿对象。
- 状态层数和游戏状态采用名称搜索。计数器支持已有值搜索与新建；计数范围独立显示。
- `lib/ruleAuthoring.ts` 提供大纲、路径解析、计数器收集和状态编号分配；展示组件复用这些纯函数。

## 草稿、身份与焦点

- `lib/statusDraftSession.ts` 按完整项目路径维护内存草稿。切换状态、卡牌与编辑页可恢复草稿；关闭应用前通过「保存状态」写入项目。
- 异步保存按提交时的草稿对象收尾；其他草稿和保存期间的更新继续保留。
- `lib/editorIdentity.ts` 使用 WeakMap 跟踪规则及效果的界面身份。不可变编辑显式继承身份，排序复用对象，复制创建新身份。身份只参与界面呈现。
- `Disclosure` 收起时保留子组件。错误定位使用 `revealDisclosureAncestors`；批量操作使用 `setDisclosuresOpen`。
- 专注工作台支持 Tab 焦点循环、Escape 返回和输入框外的 Ctrl+Z/Ctrl+Y。输入控件保留自身文本撤销。
- 规则根层按后端契约计为第1层；第8层允许叶节点，新增嵌套入口在边界收起。

## 验证

- 自动检查：`node tools/verify.mjs --scope frontend`，覆盖保存、历史、描述、规则、预览请求与草稿会话。
- 浏览器验收采用真实 Chrome 与受控 Tauri 边界，分别记录交互、中文/英文和1440×1000、1100×700布局。
- 原生交付采用启用 `tauri/custom-protocol` 的 release 构建，并检查嵌入前端资源和 Runtime 版本。游戏内战斗验证记录在对应功能交付文档。

## 官方角色卡池入口

愚者与原有官方角色一起显示在默认卡池列表。新增官方池的显示名称和项目定义集中在 `lib/officialPools.ts`，首次选择自动保存定义后再更新卡牌。已导入的同一原版池复用默认入口。异步期间按项目路径、选中卡和原始卡牌对象核对目标。
