# 导入第三方角色卡池

尖塔锻炉可以把制作的新卡注册到已安装的第三方角色 Mod 的卡池。角色本身、动画、初始卡组和专属机制仍由该角色 Mod 提供。

## 推荐使用流程

1. 安装需要的角色 Mod，以及它要求的前置 Mod。例如某些观者 Mod 需要 BaseLib。
2. 在尖塔锻炉中配置游戏目录，在卡池区域点击“从游戏读取”。编辑器会检查并更新 SpireForge Runtime；如果提示已更新或文件被游戏占用，请按提示关闭或重启游戏。
3. 启用 Runtime 和角色 Mod，启动或重启游戏，进入主菜单。Runtime 会在自己的安装目录写出 `spireforge-pools.json`。
4. 打开卡包并选择一张卡，在卡池区域点击“从游戏读取”，选择需要导入的卡池并确认。
5. 勾选导入的角色卡池，制作、保存并安装卡包。重启游戏后，用该角色验证奖励卡池、卡牌显示、战斗和存档读回。

读取到的是上一次游戏启动时的目录。新增、更新或禁用角色 Mod 后，需要重新启动游戏并再次读取。导入配置不等于安装角色 Mod，也不证明特殊角色的全部功能已兼容。

## 自定义导入与手动添加

可以导入 Runtime 生成的角色配置 JSON，也可以分享只包含所需池的配置。配置会保存在当前项目的 `project.json` 中，换电脑时随项目保留。

下面的 `ExampleRole` 和类型名都是格式示例，并非观者的真实标识：

```json
{
  "format_version": 1,
  "pools": [
    {
      "key": "mod:ExampleRole:ExampleRole.Pools.ExampleCardPool",
      "label": "示例角色",
      "mod_id": "ExampleRole",
      "type_name": "ExampleRole.Pools.ExampleCardPool",
      "workshop_id": null
    }
  ]
}
```

手动添加时需要填写显示名称、Mod ID 和完整卡池类名。Mod ID 来自该 Mod 的清单 `id`；完整类名需要从游戏导出的目录、作者文档或源码中取得。它们区分大小写。工坊 ID 可选，只填写真实的数字 ID，不能填 Mod 名称或下载链接。

普通 Mod 清单通常没有卡池类名，不能直接当作角色配置导入。DLL/PCK 中的完整角色实现也不能自动变成可编辑的卡牌数据。

## 依赖与兼容边界

卡牌 JSON 中的 `pool` 或 `pools` 使用 `mod:<Mod ID>:<完整卡池类名>`。程序只在已加载的对应 Mod 的程序集里寻找该类型，要求它是具体的 `CardPoolModel` 子类；不猜测同名类型，不在编辑器中执行第三方 DLL。

导出卡包时，会根据卡牌实际使用的第三方卡池记录所需角色 Mod。没有使用的导入配置不会添加依赖。工坊工作区只会记录已知的工坊 ID；未知 ID 需要在发布前补齐，不能认为记录了 Mod ID 就能让 Steam 自动订阅。

目标 Mod 未启用、完整类名错误或卡池注册失败时，Runtime 会在游戏日志里报告相关卡牌与卡池。多池卡中的任意目标无法解析时，整张卡会跳过注册，避免默默改变它的归属。

普通伤害、格挡、抽牌等效果可以沿用尖塔锻炉的效果系统。姿态切换、自定义资源、特殊选牌界面等需要额外的效果适配。注册成功也需要在目标角色中验证卡框、能量图标、奖励出现、战斗效果和存档；多个 Mod 为同一张卡打补丁的行为不能只靠静态检查保证。
