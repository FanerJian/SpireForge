# Mod 内容读取与编辑

适用版本：编辑器 0.2.8，Runtime 0.1.16。目录格式 2；编辑器继续读取格式 1。使用准确引用或来源覆盖的卡牌会保存为卡牌格式 2，旧编辑器会拒绝打开，避免保存时丢失新字段。

## 使用

1. 使用原来的 `editor.exe`，打开卡包，在卡牌库点击 **Mod 内容**。
2. 启用目标角色 Mod 与 Runtime，启动游戏进入主菜单。新增、禁用或更新 Mod 后重新启动游戏，并在内容库点击 **刷新**。
3. 按来源查看卡牌、状态、怪物、特殊效果或其他内容。窗口显示快照时间、读取问题和来源，读取失败时会明确说明仍在展示旧快照。
4. **用于当前卡牌**会追加相应效果。状态支持设置施加层数及目标；怪物支持召唤及实例生命配置；引用卡牌通过游戏的原生卡牌创建流程生成。
5. 卡牌可选择 **修改原卡 · 保留原行为**。导入时不修改原卡；用户编辑后只应用相应字段。费用、数值、文本、关键词和效果等修改保存在自己的卡包中。
6. **复制基础数据 · 重新配置效果**会建立新卡牌，复制费用、类型和关键词。原 Mod 的代码行为和原始描述不冒充可编辑效果，需为新卡配置效果与描述。来源卡池仍有 Mod 依赖。

原 Mod 的 DLL/PCK 文件不会被重写。覆盖在游戏初始化时作用于模型；从游戏移除或禁用自己的覆盖卡包，并重启游戏即可恢复。

覆盖卡沿用原卡的卡池、图鉴显示和升级上限。数值覆盖以变量名保存；变量可能包含自定义计算，需在目标卡牌中确认其实际用途。修改状态内部规则、怪物 AI、专属场景和自定义资源，需要相应适配。

## 长期扩展契约

- `SfContentRegistry` 从 `ModelDb.All` 发现游戏已经注册的模型，避免只依赖某些卡池或遭遇列表，也不为了扫描而实例化第三方类型。
- 内容键为 `game:<完整类型名>` 或 `mod:<真实 Mod ID>:<完整类型名>`。显示名称与身份分开，同名模型不会相互覆盖。
- 旧短名称继续兼容：原版唯一匹配优先，第三方匹配存在歧义时拒绝猜测。缺失引用记录明确错误。
- 自动生成的卡牌关联实际卡包；Runtime 的调试卡关联 Runtime，处理动态程序集对象与构建器身份不同的情况。
- `content_refs.rs` 统一处理保存、离线依赖保留、递归嵌套效果引用和发布检查。卡包清单与工坊依赖包含实际使用的来源 Mod；未知工坊 ID 会提示。
- 不同游戏目录的缓存相互隔离。所有使用目录的界面共享一次读取结果，聚焦或手动刷新时更新。
- 名称、描述、费用、数值和可编辑能力分别导出；未能读出细节的模型保留为查看项，并记录问题。

## 适配特殊命令

普通状态、卡牌、怪物模型可以直接引用。特殊姿态、资源和选牌命令需要声明式适配，或由原 Mod 注册效果。

### 声明式适配

在目标 Mod 文件目录内提供 `spireforge-actions.json`。Runtime 只查找该已加载 Mod 的程序集，要求命令为唯一的公开静态异步方法，返回 `Task` 或其子类，不支持开放泛型。

```json
{
  "format_version": 1,
  "actions": [
    {
      "name": "change_resource",
      "title": "增加资源",
      "description": "调用此角色的原生资源命令。",
      "type_name": "ExampleMod.Commands.ResourceCmd",
      "method": "Gain",
      "required_character": "ExampleMod.Characters.ExampleCharacter",
      "allowed_triggers": ["play", "on_draw"],
      "parameters": [
        { "name": "amount", "title": "数量", "type": "number", "default": 1, "min": 0, "required": true }
      ]
    }
  ]
}
```

示例的类型与方法名称是占位，需要替换成目标 Mod 的真实接口。界面根据参数描述生成数字框、文本框、枚举和复选框。

命令参数中的 `PlayerChoiceContext`、`Player`、`CardModel` 和 `Creature` 由运行上下文提供。其他参数必须与声明的 `name` 对应，仅支持字符串、布尔、整数、浮点、decimal 和枚举。需要默认值的参数应在声明里设置。复杂对象、实例命令和重载需要写一个明确的包装函数。

效果键为 `effect:<Mod ID>:<name>`。Runtime 会检查角色限制、触发时机、必填参数、枚举与数值范围。声明错误只影响对应适配项，不阻止其他内容目录生成。

观者目前附带四项适配：进入愤怒、进入平静、进入神格、退出姿态。它们调用已安装观者 Mod 的真实 `StanceCmd` 接口，并限定观者角色。版本更新导致接口变化时会报告适配失败；本次确认了注册，尚未完成实战姿态验证。

### 编程接口

其他 Mod 可以继续使用 `SfEffects.Register(string, handler)`；新增描述式重载为：

```csharp
SfEffects.Register(new SfEffectDescriptor(
    "ExampleMod", "change_resource", "增加资源", "使用原生资源机制。",
    [new SfEffectParameter("amount", "数量", "number", Default: 1, Min: 0, Required: true)]),
    async context => { /* 调用此 Mod 的实际命令 */ });
```

同一完整效果键不能静默覆盖其他处理器。已有旧注册接口的行为保持兼容。

## 验证与边界

本次在真实游戏程序的无界面启动中读取到六个角色内容，并分别覆盖一张卡牌的费用和伤害变量，核对原始名称和描述保持不变。目录没有报告读取问题。临时验证包已移出游戏目录，并再次启动游戏恢复正常目录。

真实 Chromium 验证了来源筛选、详情、导入与修改流程，使用真实游戏目录数据和受控的 Tauri 调用替身；这不等于桌面 WebView2 验收。后端、存储和打包验证另行执行。

尚未完成所有卡牌的实战、升级、多人和存档流程；怪物特殊遭遇要求与姿态命令实战仍需专项验证。此机制可以持续接入新 Mod，但不能保证自动把任意 C# 行为变成可编辑积木。当前其他模型支持查看，完整行为编辑需要对应协议或适配。

状态与怪物的完整创作面板不是本次交付范围。视觉特效保持既有能力，任意 PCK 内场景及自定义资源命令需额外声明或适配。
